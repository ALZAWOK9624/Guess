## What Went Well

- All 8 stories completed with zero blockers
- Backend test coverage grew from 0 to 43 tests, all passing with no regression
- Review density decreased over time (Story 1.2: 10 patches → Story 1.5a/1.6: 2 patches), showing effective learning
- Consistent deferred decision pattern — v2 features correctly postponed (rate limiting, pagination, audit logs)
- Zero production incidents or deployment issues
- Foundational infrastructure (CI, Docker Compose, design tokens, auth) built solid for subsequent epics

## Challenges & Learnings

- Early stories (1.2, 1.3) required more review patches due to a11y, cross-browser, and JWT error handling gaps
- JWT `ExpiredSignatureError` vs `JWTError` distinction needed explicit handling (caught in review)
- Debounce cleanup on component unmount was missed in initial implementation
- Story 1.1 remained in `review` status until retrospective — resolved by marking `done`
- conftest.py evolved from placeholder to shared fixtures, but only covers SQLite in-memory (not PostgreSQL-specific scenarios)

## Key Insights

1. **Review quality improves over time** — earlier stories need more scrutiny; later stories benefit from accumulated patterns
2. **Test infrastructure is critical** — shared conftest fixtures established in Story 1.5a became the foundation for all subsequent tests
3. **Deferred items are healthy** — not every edge case needs solving in v1; clear defer documentation avoids confusion
4. **No user-facing issues reported** — the core auth flow (register → login → password reset → guest access) is smooth
