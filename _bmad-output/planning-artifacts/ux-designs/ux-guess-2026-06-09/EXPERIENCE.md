# Guess — Experience Spine

> 赛马爱好者圈子的专属竞猜平台。移动优先、邀请制、JRA 精密美学。Vue3 + FastAPI + PostgreSQL。`DESIGN.md` 是视觉身份参考，本脊柱拥有行为、交互、信息架构和流程。

## Foundation

**Form factor**: 移动优先（320–428px 为主要设计面），桌面增强（1024px+ 管理后台侧边栏布局）。响应式，单代码基。

**UI system**: 无命名 UI 系统。纯手工 Vue3 组件，CSS 变量绑定 `DESIGN.md` 的 `{colors.*}` / `{typography.*}` / `{rounded.*}` / `{spacing.*}` 令牌。组件视觉规格见 `DESIGN.md.Components`；本脊柱定义行为。

**Platform conventions**: 移动端遵循平台原生交互（iOS/Android 均支持触摸拖拽、回弹滚动、原生键盘行为）。桌面端使用鼠标悬停态、键盘快捷键（管理后台）。

**Light mode only in v1**, 无暗色模式。`DESIGN.md` 仅定义亮色色板。

### Navigation

**移动端（<768px）**:
- 底部固定导航栏：`首页` | `排行榜`（+ 管理员可见 `管理`）
- 比赛详情页顶部有返回箭头
- 管理后台内使用 Tab 切换（比赛 / 马匹 / 邀请码）或汉堡菜单

**桌面端（≥1024px）**:
- 顶部固定导航栏：Logo + `首页` `排行榜` + 右侧登录/用户信息
- 管理员额外显示 `管理` 入口
- 管理后台：左侧 240px 固定侧边栏（仪表盘 / 比赛 / 马匹库 / 邀请码），主内容区独立滚动

**导航规则**:
- 游客点击投票按钮 → 弹出登录提示，跳转登录页
- 登录成功后回到来源页面
- 管理后台入口对非管理员不可见

→ IA 闭合检查：每条 PRD 用户旅程都有对应表面；每个表面都有至少一条到达路径。

## Voice and Tone

微文案。品牌语调和美学姿态见 `DESIGN.md.Brand & Style`。

| 场景 | Do | Don't |
|---|---|---|
| 投票确认 | "你已投给：{马名}" | "投票成功！🎉" |
| 投票修改 | "修改投票" | "换一匹试试？" |
| 投票锁定后 | "投票已截止" | "来晚了！已经锁定了" |
| 登录失败 | "用户名或密码错误" | "密码不正确"（不过度具体） |
| 注册邀请码无效 | "邀请码无效或已被使用" | 无 |
| 游客点投票 | "请先登录或注册" | 无，不弹窗打断 |
| 空排行榜 | "还没有人参与竞猜——成为第一个！" | "无数据" |
| 拖拽录入提示 | "拖拽马匹按最终名次排列" | 冗长说明文字 |
| 结算完成 | "积分已更新"（排行榜自动刷新） | "结算成功！" |
| 删除比赛确认 | "确定删除「{比赛名}」？所有投票记录将被清除。" | "你确定吗？" |
| 自定义规则提示 | "自定义规则仅作用于本场比赛，不会保存为模板。" | 无 |

**原则**: 短句、完整、陈述事实。无感叹号、无 Emoji、无 gamified 语言。JRA 克制语调：像赛事公告，不像产品推销。

## State Patterns

| State | Surface | Treatment |
|---|---|---|
| **空比赛列表** | 首页 | "还没有比赛。管理员正在筹备中——" 居中展示，灰色文字。不对游客显示。 |
| **投票中 — 已投票** | 比赛详情 | 投票按钮变为 `{components.vote-confirmed}`。马匹列表中当前用户投的马高亮金色边框 + "你选了这匹"标记。 |
| **投票中 — 未投票** | 比赛详情 | 金色投票按钮活跃。马匹列表无标记。 |
| **投票已锁定 — 你投了** | 比赛详情 | 显示"投票已截止"。你的投票结果固定展示。 |
| **投票已锁定 — 你没投** | 比赛详情 | 显示"投票已截止。你未参与本场竞猜。" |
| **已结算** | 比赛详情 | 马匹按最终名次排列，名次标签（1st/2nd/3rd…）显示。每位用户的投票旁显示该场所获积分。 |
| **空排行榜** | 排行榜 | "还没有人参与竞猜——成为第一个！" + 跳转首页链接。 |
| **未登录** | 全局 | 所有页面内容可读（公开信息）。投票按钮点击 → 跳转登录页（带 `?redirect=` 参数）。登录成功 → 回到来源页。 |
| **注册 — 邀请码无效** | 注册页 | 输入框下方红色提示："邀请码无效或已被使用"。 |
| **注册成功** | 注册页 → 首页 | 自动登录，跳转首页。无欢迎弹窗——直接进入比赛列表。 |
| **拖拽结果未完成** | 结果录入页 | 确认按钮置灰，提示"请排列所有马匹的名次（含弃权区）"。 |
| **拖拽结果已确认** | 结果录入页 → 比赛详情 | 结算完成 → 自动跳转该比赛详情页，排行榜即时刷新。 |
| **修改已结算结果** | 结果录入页 | 预填上次排名顺序。修改确认 → 撤销旧积分、重算、更新排行榜。过程无感知延迟（<1s）。 |
| **马匹库为空** | 管理马匹库 | "马匹库为空——创建第一场比赛时，参赛马匹将自动入库。" |
| **加载中** | 全局 | Skeleton 占位符：比赛卡片骨架（灰条模拟标题行 + 属性行），不超过 500ms。排行榜加载中显示表头 + 5 行骨架行。 |
| **网络错误** | 全局 | 投票提交换算为乐观更新 + 后台重试。加载失败显示"加载失败，请刷新重试" + 刷新按钮。关键操作（结算确认）失败显示错误提示，可重试。 |

## Interaction Primitives

- **Tap** 为主要交互。所有可点击元素触摸区域 ≥ 44px（移动端）。
- **Long-press** 仅用于拖拽排序的激活（300ms 阈值）。无右键菜单，无长按上下文菜单。
- **Drag** 仅用于管理员结果录入界面。桌面端鼠标拖拽；移动端长按后拖拽。拖拽视觉反馈：卡片半透明 + 轻微抬起阴影，目标插入位置绿色高亮条。
- **Pull-to-refresh** 首页比赛列表支持下拉刷新。排行榜支持。
- **Swipe** 不用于任何操作——避免与拖拽排序冲突。
- **Keyboard** 管理后台支持基本快捷键：`Esc` 关闭弹窗、`Enter` 确认表单。
- **Banned**: 轮播图、开屏动画、庆祝动效、徽章计数、推送通知重激活、弹窗叠加层超过一层。

## Accessibility Floor

行为层。视觉对比度见 `DESIGN.md.Colors`。

- **语义 HTML**: 所有页面使用正确的 heading 层级（h1→h2→h3）。表格使用 `<table>` + `<th scope>`。表单使用 `<label>` 绑定。
- **触摸目标**: 所有可交互元素 ≥ 44×44px（移动端）。拖拽手柄 ≥ 48×48px。
- **焦点可见**: 所有可聚焦元素有可见 focus ring（2px `{colors.primary}` 外描边，2px 偏移）。Tab 顺序跟随视觉阅读顺序。
- **颜色不是唯一指示器**: 状态胶囊同时使用文字 + 颜色。等级徽章使用文字（G1/G2）+ 颜色。投票确认使用 ✓ + 文字 + 颜色。积分正负使用 +/- 符号 + 颜色。
- **减少动画**: `prefers-reduced-motion` 被尊重——拖拽动画、骨架屏脉冲、徽章切换动画全部跳过。
- **对比度**: 正文-背景 ≥ 4.5:1，大标题 ≥ 3:1。金色 `#B8960C` 在白色背景上仅用于大字号徽章和按钮（满足 3:1），不用于小号正文。
- **屏幕阅读器**: 比赛卡片朗读"G1 日本德比，投票中，12匹参赛"。排行榜朗读"第1名，小丽，85分"。拖拽卡片朗读位置 + 马名。

## Key Flows

### Flow 1 — 小丽用手机投票（UJ-2）

**Persona**: 小丽，赛马爱好者。手机收到群消息"日本德比可以投票了"。

1. 小丽在微信中点开网站链接 → 首页加载，日本德比卡片在列表顶部（`G1` 金色徽章，状态"投票中"）。
2. 看到有 8 位朋友已投票（卡片显示"8人已投"）。
3. 点击日本德比卡片 → 进入比赛详情页。看到 12 匹参赛马，每位朋友投了哪匹一目了然。
4. 她还没登录 → 点击底部金色"投票"按钮 → 跳转登录页。
5. 输入用户名密码 → 登录成功 → 自动回到日本德比详情页。
6. 浏览马匹，点击一匹 → 卡片边框变金，显示勾选 → 点击"确认投票"。
7. **Climax**: 页面刷新投票明细，小丽的名字出现在该马匹下方 `小丽 → {马名}`。投票按钮变为绿底"✓ 已投：{马名}"。她可以在手机上直接看到所有人的选择，包括自己刚投的。

**Mobile check**: 全部操作 ≤ 3 次点按（选马 → 确认）。全屏单列，无缩放。

### Flow 2 — tkd 创建比赛 (UJ-1)

**Persona**: tkd，管理员。周六有一场 G1 日本德比，需要在周四前创建好。

1. 桌面端登录 → 顶部导航点击"管理" → 进入管理仪表盘。
2. 点击"创建比赛" → 进入创建表单。
3. 填写比赛名称"日本德比"、日期（日期选择器）、等级选"G1"。
4. 在"参赛马匹"搜索框中输入"春秋分" → 下拉结果出现，勾选。继续搜索添加其他马匹。一匹新马"ドウデュース"不在库中 → 点击"新建马匹"→ 弹出快捷表单（名字必填，其余选填）→ 保存后自动加入本场。
5. 确认所有信息 → 点击"创建"。
6. **Climax**: 跳转首页，日本德比卡片出现在列表顶部，状态"投票中"。

**Success metric check**: 创建流程 ≤ 2 分钟。

### Flow 3 — tkd 锁定投票并录入结果 (UJ-3)

**Persona**: tkd，比赛即将开始。

1. 管理后台 → 找到日本德比 → 点击"锁定投票"→ 二次确认弹窗"确定锁定「日本德比」？锁定后所有用户不可投票或修改。" → 确认。
2. 比赛状态变为"已锁定"🔒。
3. 赛后，回到管理后台 → 点击"录入结果"→ 进入拖拽排序界面。
4. 12 张马匹卡片以初始排列展示。左侧拖拽手柄（⠿），右侧马匹名 + 关键属性。
5. tkd 按实际名次拖拽排序：第一名拖到顶部，第二名紧随其后……有一匹马退赛 → 拖入"弃权区"。
6. 所有马匹排完 → 底部"确认结果"按钮激活 → 点击。
7. **Climax**: 系统即时结算积分。页面自动跳转比赛详情——所有用户的投票旁显示所获积分（+10 / -10 / 0 等），排行榜自动刷新。tkd 快速扫一眼，确认无人投退赛马。

**Edge case**: 如果搞错了第 3、4 名顺序 → 重新进入结果录入 → 调整 → 确认 → 旧积分撤销，新积分重算，整个过程 < 1 秒。

### Flow 4 — 游客浏览排行榜和比赛结果 (UJ-4)

**Persona**: 路人，被群友分享的排行榜链接吸引。

1. 打开链接 → 排行榜页面。看到积分排名，第一名 85 分（金色排名数字），第二名 72 分。
2. 点击某场比赛 → 查看详情：参赛马匹最终排名、每位用户的投票和积分明细。
3. **Climax**: 产生兴趣 → 点击右上角"登录"→ 底部"没有账号？注册"→ 输入邀请码。需要向群主索取。
4. 拿到邀请码后 → 注册 → 自动登录 → 首页比赛列表。下次比赛开始就可以投票了。

### Flow 5 — 修改已结算结果（FR-22 容错）

1. 管理后台 → 找到一场已结算比赛 → 点击"修改结果"。
2. 进入拖拽界面，预填上次的排名顺序。
3. 调整 → 确认。
4. **Climax**: 该场比赛原积分全部撤销 → 按新排名重算 → 排行榜即时反映变更。积分变更记录可追溯（时间戳 + 变更内容）。

## Inspiration & Anti-patterns

- **Lifted from JRA (jra.jp)**: 精密仪器式克制——网格布局、绿色品牌色、留白驱动信息密度、状态靠文字双表达而非纯颜色。
- **Lifted from JRA rebrand (GK Graphics, 1987)**: "马是美丽的"——将赛马定位为健康智性体育，而非赌博。Guess 承载同一理念。
- **Rejected — Gamification (Duolingo, most habit apps)**: 连胜计数器、成就徽章、推送催促。Guess 是朋友间的荣誉积分游戏，不需要机器生成的激励——排名本身就是激励。
- **Rejected — Real-time betting UI (sportsbook apps)**: 赔率闪烁、动态赔率条、红色绿色跳动数字。Guess 不是博彩平台——无赔率、无实时下注、无金钱。
- **Rejected — Social feed (Instagram/Twitter model)**: 评论、点赞、互动、个人主页。v1 不做社交——圈子互动在群聊完成，平台负责投票+积分。

## Responsive & Platform

**断点策略**: 单一主断点 768px。
- <768px: 移动端布局。单列。底部固定导航。全宽卡片。表格水平滚动。
- ≥768px: 桌面端布局。顶部固定导航。内容居中 max-w-7xl。管理后台侧边栏（240px）+ 主内容区。

**平台差异**:
- iOS Safari: 底部导航需 `safe-area-inset-bottom` 适配刘海屏。拖拽需 `touch-action: none`。
- Android Chrome: 同上。回弹滚动默认行为。
- 桌面 Chrome/Edge/Safari: 鼠标悬停态 + 键盘 Tab 导航。

**表格响应式**: 排行榜和马匹列表在移动端水平滚动（`overflow-x: auto`），关键列（排名、用户名、积分）始终可见，次要列（场数、场均）可滚动查看。不做响应式表格折叠/堆叠——数据完整性优先于视觉适配。
