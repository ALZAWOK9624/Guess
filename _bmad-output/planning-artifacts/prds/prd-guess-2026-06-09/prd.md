# PRD: Guess

*赛马爱好者圈子的专属竞猜游乐场。*

## 0. Document Purpose

本文档面向产品经理、UX 设计师、架构师和开发团队，描述 Guess 平台 v1 的完整需求。文档以 Glossary 锚定领域术语，功能按模块分组并嵌套编号的 FR，内联 `[ASSUMPTION]` 标记未经确认的推断。本 PRD 基于 `brief-guess-2026-06-08` 产品简报，并吸收了 2026-06-09 的用户访谈内容。

## 1. Vision

Guess 是一个面向约 100 人赛马爱好者圈子的竞猜投票平台。一群朋友长期通过腾讯问卷对全球各大赛马比赛进行竞猜——投票、人工算分、截图发群。Guess 把这一切搬到线上，让投票更专业、排名更直观、积分自动结算。

它不是一个博彩产品——没有金钱下注，纯粹是朋友间的荣誉积分游戏。它不是一个通用投票工具——积分规则直接内嵌，用户不碰 Excel、管理员不手算。它就是**这个圈子的专属游乐场**。

首版目标：跑稳核心循环（创建比赛 → 投票 → 锁定 → 录入结果 → 结算积分 → 查看排名），让前 10 场赛事后几乎所有人从问卷迁移至此。

## 2. Target User

### 2.1 Jobs To Be Done

**普通用户（朋友）：**
- 快速完成投票：打开 → 选马 → 确认，不超过 3 次点击。
- 查看自己和朋友的排名变化，了解谁是当季最强预测者。
- 回顾过往比赛结果和自己的投票记录。
- 感受到「这是一个我们自己的地盘」——邀请制带来的归属感。

**管理员（1-2 人，当前为 tkd）：**
- 创建并管理比赛：填写信息、选择参赛马匹、指定等级规则。
- 维护马匹库：添加、更新马匹数据，避免每场重复录入。
- 控制投票节奏：在适当时间锁定投票，防止比赛开始后修改。
- 录入比赛结果：通过直观的拖拽排序操作完成，允许随时修正。
- 管理圈子成员：生成邀请码，控制准入门槛。

### 2.2 Non-Users (v1)

- 不面向公众开放注册——仅凭邀请码加入。
- 不面向大型社区（>500 人）——不优化社交网络效应。
- 不面向博彩/金钱交易场景。

### 2.3 Key User Journeys

- **UJ-1. 管理员创建一场新比赛。**
  - **Persona + context:** tkd，圈子管理员，在赛事日程表中看到本周六有一场 G1 日本德比。
  - **Entry state:** 已登录，在管理后台首页。
  - **Path:** 点击「创建比赛」→ 填写比赛名称、日期、等级（选 G1）→ 从马匹库中搜索并勾选参赛马匹（若某马不在库中，快速新建）→ 确认创建。
  - **Climax:** 比赛出现在首页的「进行中」区域，状态为「投票中」，用户列表自动收到可投票通知。
  - **Resolution:** tkd 回到首页，看到比赛已列出，准备在群聊中通知大家投票。
  - **Edge case:** 创建时漏选了一匹马。管理员可在投票锁定前随时编辑马匹列表。

- **UJ-2. 一位朋友完成投票。**
  - **Persona + context:** 小丽，赛马爱好者，手机上看到群消息说「日本德比可以投票了」。
  - **Entry state:** 未登录，在手机浏览器打开网站，看到比赛列表中展示的日本德比及其参赛马匹。
  - **Path:** 点击「登录」→ 输入用户名密码 → 回到比赛列表 → 点击日本德比 → 浏览参赛马匹 → 点击「选这匹」选中一匹 → 确认投票。
  - **Climax:** 页面显示「你已投票：{马名}」，同时该比赛实时展示每位用户投了哪匹马（所有人的选择互相可见）。
  - **Resolution:** 小丽关掉页面，等比赛结果。
  - **Edge case:** 小丽想换一匹马。点击「修改投票」，重新选择，在管理员锁定之前可以无限次更换。

- **UJ-3. 管理员锁定投票并录入结果。**
  - **Persona + context:** tkd，比赛即将开始。
  - **Entry state:** 已登录，管理后台。
  - **Path:** 在管理后台找到日本德比 → 点击「锁定投票」→ 系统确认→ 投票通道关闭 → 赛后 → 点击「录入结果」→ 出现拖拽排序界面，所有参赛马匹以卡片形式展示 → 拖拽卡片按 1-2-3-... 顺序排列 → 确认。
  - **Climax:** 系统自动按 G1 规则结算所有用户的积分，排行榜即时刷新。
  - **Resolution:** tkd 查看排行榜，确认积分无误，结果全员可见。
  - **Edge case:** 录入时搞错了第 3 和第 4 名。tkd 可随时重新编辑结果，系统自动重算并覆盖积分。

- **UJ-4. 游客浏览比赛和排行榜。**
  - **Persona + context:** 圈子外朋友，被群友分享链接引来，未注册。
  - **Entry state:** 未登录，浏览器打开。
  - **Path:** 首页查看所有已完成比赛的结果 → 点击某场查看详情（参赛马匹、投票分布、最终排名）→ 切换到积分榜页面，查看所有人的累计积分和排名。
  - **Climax:** 对圈子产生兴趣，问群主要邀请码。
  - **Resolution:** 拿到邀请码后注册加入。
  - **Edge case:** 游客无法投票——点击投票按钮时提示「请先注册或登录」。

## 3. Glossary

- **比赛 (Race)** — 一场赛马赛事。拥有名称、日期、等级、参赛马匹列表、状态（投票中 / 已锁定 / 已结算）。
- **马匹 (Horse)** — 一匹参赛马。存在于马匹库中，可被多场比赛复用。属性含：**名字**（必填）、**性别**、**年龄**、**产地**、**父马**（sire）、**母父马**（damsire）、**负重**（weight）、**骑手**（jockey）、**前走成绩**（previous race results）、**主胜鞍**（best winning race）。所有字段可手动修改，同时各自具备自动更新逻辑。
- **比赛等级 (Race Grade)** — 决定积分规则的分类标签。可选值：G1、G2 / JPN1、2岁 G1、自定义。
- **积分规则 (Scoring Rule)** — 一种等级与积分映射关系。G1 含正分与末位扣分（按匹数分档）；G2/JPN1 仅正分无扣分；2岁 G1 正分同 G1 规则但无扣分；自定义由管理员自由设定正序分数与扣分规则。
- **投票 (Vote)** — 用户在一场比赛中选择一匹马的行为。每用户每场比赛仅有一个有效投票，管理员锁定前可修改。
- **锁定 (Lock)** — 管理员操作，关闭一场比赛的投票通道。锁定后用户不可投票或修改。
- **结算 (Settle)** — 管理员录入名次后，系统根据积分规则为所有投票用户计算并累加积分的过程。
- **退赛 / 未完成 (Scratched / DNF)** — 马匹未参赛或未完成比赛。按弃权处理，选中该马的用户不获得积分。
- **积分 (Points)** — 用户预测准确度的量化值。全局累计，排行榜以此排序。
- **排行榜 (Leaderboard)** — 所有用户按累计积分降序排列的页面。
- **邀请码 (Invite Code)** — 管理员生成的身份凭证，每个码终生绑定一个用户。注册时凭码加入，后续凭码找回密码。管理员可在后台查询任意用户的邀请码和绑定 QQ 号，用于身份管理和圈子维护。
- **游客 (Guest)** — 未登录的网站访问者。可查看所有比赛结果、投票统计和排行榜，但不可投票。

## 4. Features

### 4.1 用户认证与邀请制注册

**Description:** 用户通过管理员生成的邀请码注册账户。登录后获得投票权限。游客（未登录）仅可浏览公开信息。实现 UJ-2、UJ-4。

**Functional Requirements:**

#### FR-1: 管理员生成邀请码
管理员生成邀请码，每个码终生绑定一个用户，不与其他人共享。管理员在后台将邀请码与用户的 QQ 号绑定，后续可随时查询。邀请码是用户的永久身份凭证，用于注册和密码找回。

**Consequences (testable):**
- 管理后台可查看所有邀请码及其绑定状态（未绑定 / 已绑定用户名 / 已绑定 QQ）。
- 管理员可按用户名、邀请码、QQ 号三个维度互相查询。
- 管理员可随时失效某个邀请码（用户将无法登录和找回密码）。

#### FR-2: 用户凭邀请码注册
用户访问注册页，输入用户名、密码、QQ 号和有效的未绑定邀请码完成注册。该邀请码此后与用户终生绑定。忘记密码时，通过输入用户名和该用户的邀请码来重置密码。

**Consequences (testable):**
- 已被其他用户绑定的邀请码拒绝注册并提示。
- 无效或已失效邀请码拒绝注册并提示。
- 用户名全局唯一，重复时提示。
- 注册成功后自动登录。
- 密码找回：输入正确用户名+该用户绑定邀请码 → 进入重置密码流程。
- 管理后台可查询到该用户绑定的邀请码和 QQ 号。

#### FR-3: 用户登录
已注册用户凭用户名与密码登录。

**Consequences (testable):**
- 登录成功后进入首页，所有投票操作可用。
- 错误凭据返回明确但不过度具体的错误提示（如「用户名或密码错误」）。

#### FR-4: 游客只读访问
未登录用户可访问首页、已完成比赛详情页和排行榜。不可投票。

**Consequences (testable):**
- 点击投票按钮显示「请先登录或注册」提示。
- 所有页面无需登录即可访问（内容可读）。

### 4.2 马匹库管理

**Description:** 管理员维护一个全局马匹库，每匹马的属性包含 10 个字段。创建比赛时从库中搜索选择马匹，也可即时新建。库中马匹信息可由管理员随时手动编辑，同时各字段支持独立的自动更新逻辑——管理员不必每场手工追踪数据变更。赛事详情页面向所有用户展示马匹的完整属性。实现 UJ-1、UJ-4。

**Functional Requirements:**

#### FR-5: 马匹属性定义
每匹马拥有以下 10 个属性：

| 属性 | 字段名 | 说明 | 必填 |
|------|--------|------|------|
| 名字 | name | 马匹名称 | ✓ |
| 性别 | sex | 牡/牝/骟 | — |
| 年龄 | age | 岁数 | — |
| 产地 | origin | 出生国家/地区 | — |
| 父马 | sire | 父系 | — |
| 母父马 | damsire | 母父（母系父马） | — |
| 负重 | weight | 比赛负重（kg） | — |
| 骑手 | jockey | 当场骑手 | — |
| 前走成绩 | previous_result | 上一场比赛名次/描述 | — |
| 主胜鞍 | best_win | 生涯最佳胜鞍 | — |

**Consequences (testable):**
- 名字为唯一必填字段，其余可空。
- 编辑马匹后，已关联该马匹的过往比赛数据不受影响（历史数据保留快照）。
- 马匹库支持按名字模糊搜索。

#### FR-6: 马匹属性手动编辑
管理员可在管理后台手动修改任意马匹的任意属性值。

**Consequences (testable):**
- 每个字段均可单独编辑、保存。
- 编辑不触发自动更新逻辑（手动输入为最终值，覆盖自动结果）。

#### FR-7: 马匹属性自动更新
每个属性各自具备自动更新逻辑，管理员无需逐场手工追踪数据变更。`[ASSUMPTION: 自动更新触发时机为管理员录入比赛结果时——系统根据该场比赛的实际数据，按各字段的更新规则自动推送到马匹库。管理员可随时手动覆盖自动结果。]`

**Consequences (testable):**
- 自动更新作用于比赛所在赛事的马匹记录，不影响历史快照。
- 自动更新仅填充空字段或按规则覆盖旧值；已被管理员手动编辑过的字段在后续自动更新中不覆盖（手动优先）。
- 自动更新的字段变更对用户可追溯（显示「自动更新」来源标记）。

**Out of Scope:**
- v1 不定义每个字段的具体自动更新规则——规则由管理员在后续版本中逐步配置。v1 仅搭建自动更新框架和触发机制。

#### FR-8: 创建比赛时从库中选择马匹
管理员创建比赛时，通过搜索框从马匹库中勾选参赛马匹。若某马不在库中，可即时新建并同时加入本场比赛。

**Consequences (testable):**
- 搜索框支持模糊匹配。
- 即时新建的马匹自动入库，后续比赛可直接选用。

#### FR-9: 赛事页面展示马匹详情
任何用户（含游客）在比赛详情页查看参赛马匹时，可见每匹马的完整 10 项属性。

**Consequences (testable):**
- 比赛详情页以卡片或表格形式列出所有参赛马匹及其全属性。
- 信息来源于该场比赛创建时的马匹数据快照（而非马匹库的实时数据），确保比赛页面的展示与投票时的数据一致。

### 4.3 比赛管理与等级规则

**Description:** 管理员创建、编辑比赛。每场比赛绑定一个等级，等级决定积分规则。支持 G1（含匹数分档扣分）、G2/JPN1、2岁 G1 和自定义四种等级。不允许删除已结算比赛，只能修改结果。实现 UJ-1。

**Functional Requirements:**

#### FR-10: 管理员创建比赛
管理员填写比赛名称、日期、选择等级，从马匹库中勾选参赛马匹，完成创建。创建后比赛状态为「投票中」。

**Consequences (testable):**
- 比赛名称、日期、等级、至少 2 匹参赛马为必填项。
- 创建成功后比赛出现在首页比赛列表。
- 管理员可在投票锁定前编辑比赛信息（包括增删马匹）。

#### FR-11: 管理员删除比赛
管理员可删除投票中或已锁定但未结算的比赛。已结算比赛不可删除，只能通过 FR-22 修改结果来更正。

**Consequences (testable):**
- 未结算比赛（投票中/已锁定）可删除，删除同时清除该比赛的所有投票记录。
- 已结算比赛的「删除」按钮置灰/隐藏，提示「已结算比赛不可删除，请修改结果」。
- 删除操作需二次确认。

#### FR-12: 积分规则引擎 — G1
G1 级别：第 1 名 +10、第 2 名 +5、第 3 名 +3、第 4 名 +2、第 5 名 +1。
末位扣分按参赛马匹数分档：
- ≥8 匹：倒数第 1 名 -10、倒数第 2 名 -5、倒数第 3 名 -1。
- 7 匹：倒数第 1 名 -5、倒数第 2 名 -1。
- 6 匹：仅倒数第 1 名 -1。
- ≤5 匹：无扣分。

**Consequences (testable):**
- 以 ≥8 匹比赛为例，用户投中第 1 名得 +10，投中第 3 名得 +3，投中倒数第 1 名得 -10，投中第 6 名（非前 5 非末 3）得 0。
- 退赛 / DNF 马匹按弃权处理：选中该马的用户得 0 分，不计入排名扣分。

#### FR-13: 积分规则引擎 — G2 / JPN1
G2 / JPN1 级别：第 1 名 +5、第 2 名 +4、第 3 名 +3、第 4 名 +2、第 5 名 +1。不扣分。

**Consequences (testable):**
- 无论参赛马匹数量，无末位扣分。
- 投中第 6 名及以后得 0 分。

#### FR-14: 积分规则引擎 — 2 岁 G1
2 岁 G1 级别：正分规则同 G1（+10、+5、+3、+2、+1），但不扣分。

**Consequences (testable):**
- 规则与 G1 完全相同，仅移除末位扣分逻辑。
- 投中末位不得负分。

#### FR-15: 积分规则引擎 — 自定义
管理员创建比赛时选择「自定义」等级，为该场比赛单独设定正序积分列表（第 1 名至第 N 名的分值）和末位扣分规则（扣分档位与匹数条件）。自定义规则为一次性，不保存为模板。

**Consequences (testable):**
- 创建时正序积分列表为必填，末位扣分规则为选填。
- 该规则仅作用于当前比赛，不在后续比赛中复用。

### 4.4 投票

**Description:** 用户在一场开放比赛中选择一匹参赛马。管理员锁定前可任意修改。实现 UJ-2。

**Functional Requirements:**

#### FR-16: 用户投票
已登录用户在「投票中」状态的比赛中，从参赛马匹列表中选择一匹并确认。每用户每场比赛仅持有一个有效投票。

**Consequences (testable):**
- 投票确认后，页面显示当前投票状态（已投马匹名）。
- 重复确认同一场比赛时覆盖旧投票。
- 投票操作不超过 3 次点击/触屏交互。

#### FR-17: 投票修改
管理员锁定投票前，用户可更换选择，不限次数。

**Consequences (testable):**
- 用户点击「修改投票」重新进入选择界面。
- 旧投票被新选择覆盖。

#### FR-18: 投票不可修改（锁定后）
管理员锁定比赛后，任何用户不可新增投票或修改已有投票。

**Consequences (testable):**
- 锁定后比赛页面显示「投票已截止」。
- 已投票用户可见自己的最终选择。

### 4.5 结果录入与结算

**Description:** 管理员锁定比赛后，通过拖拽排序界面录入马匹最终名次。确认后系统自动按等级规则结算积分。结果可随时修改，修改后重算积分。实现 UJ-3。

**Functional Requirements:**

#### FR-19: 管理员锁定投票
管理员对一场比赛执行「锁定投票」操作，此后用户不可投票或修改。

**Consequences (testable):**
- 锁定操作需二次确认。
- 锁定后比赛状态变为「已锁定」。
- 锁定不可撤销（但管理员可继续录入/修改结果）。

#### FR-20: 管理员通过拖拽排序录入结果
管理员进入结果录入界面，看到所有参赛马匹以卡片形式排列。通过拖拽将马匹按实际名次（第 1 名到第 N 名）排序，确认提交。

**Consequences (testable):**
- 拖拽过程中卡片随手指/鼠标移动，插入位置有视觉高亮。
- 所有参赛马匹必须全部排列且名次不重复。
- 确认后触发自动结算。

#### FR-21: 系统自动结算积分
结果确认后，系统立即按比赛等级的积分规则，为所有已投票用户计算并累加积分到用户总分。

**Consequences (testable):**
- 结算完成后比赛状态变为「已结算」。
- 排行榜即时反映最新积分。
- 积分计算结果与人工按规则计算完全一致（零差异）。
- 退赛/DNF 马匹对应的投票得 0 分。

#### FR-22: 管理员修改已结算结果
管理员可随时重新编辑一场已结算比赛的结果。修改确认后，系统撤销该比赛的原积分，重新结算。

**Consequences (testable):**
- 修改结果后，所有受影响用户的积分即时更新。
- 排行榜自动刷新。
- 积分变更历史可追溯（记录每次修改的时间戳和变更内容）。

### 4.6 排行榜与公开查看

**Description:** 所有用户和游客均可查看排行榜（全局累计积分排名）和每场比赛的详细结果。投票中比赛实时展示每位用户投了哪匹马。实现 UJ-3、UJ-4。

**Functional Requirements:**

#### FR-23: 全局排行榜
排行榜页面展示所有已注册用户的累计积分，按积分降序排列。

**Consequences (testable):**
- 排行榜在每次比赛结算后即时刷新。
- 游客和已登录用户均可访问排行榜。
- 展示字段：用户名、累计积分、参与比赛场数、场均得分（累计积分 ÷ 参与场数）。

#### FR-24: 比赛详情公开查看
任何人（含游客）可查看已结算比赛的详情：参赛马匹列表、最终排名、每位用户的投票选择和获得的积分。

**Consequences (testable):**
- 比赛详情页无需登录即可访问。
- 展示完整投票分布和积分明细。

#### FR-25: 投票中比赛实时投票展示
任何人（含游客）在投票中比赛页面可看到每匹马的投票详情——哪位用户投了哪匹马。投票信息实时更新。

**Consequences (testable):**
- 投票中比赛页面展示每位用户头像/名称及其选择（如「小丽 → 春秋分」）。
- 用户提交或修改投票后，展示即时刷新。
- 游客和已登录用户均可查看完整投票明细。

### 4.7 响应式界面

**Description:** 网站适配桌面和移动端浏览器，手机为主要使用场景。

**Functional Requirements:**

#### FR-26: 响应式布局
所有页面在移动端（最小宽度 320px）和桌面端均可正常浏览和操作。

**Consequences (testable):**
- 核心操作流（投票、查看排行榜）在移动端完成不超过 3 次点击/滑动。
- 拖拽排序界面在移动端支持触摸拖拽。
- 所有文字在移动端可读（不小于 14px 基准字号）。

## 5. Non-Goals (Explicit)

- 不做实时赔率或动态赔率系统。
- 不做金钱下注、虚拟币系统或任何形式的博彩。
- 不做微信/第三方 OAuth 登录。
- 不做社交功能：评论、点赞、私信、头像、个人主页。
- 不做外部赛马数据 API 对接——比赛信息由管理员手动录入。
- 不做消息推送/通知——投票提醒通过群聊完成。
- 不做多语言——仅中文。
- 不做赛季/年度积分重置——v1 使用累计积分。

## 6. MVP Scope

### 6.1 In Scope

- 邀请制注册（管理员生成邀请码，终生绑定用户和 QQ，凭码注册与找回密码）
- 马匹库管理（管理员增删改马匹信息）
- 比赛管理：创建、编辑比赛；已结算比赛不可删除仅可修改结果
- 四种比赛等级规则引擎：G1（匹数分档扣分）、G2/JPN1、2岁 G1、自定义
- 投票：已登录用户每场比赛选一匹马，锁定前可修改
- 投票锁定：管理员手动锁定单场比赛
- 结果录入：拖拽排序马匹，确认后自动结算积分
- 结果修改：已结算结果可随时修改，改后重算积分
- 全局排行榜：所有用户累计积分排名
- 比赛详情公开：游客和用户均可查看已结算比赛的完整信息和投票记录
- 响应式 UI：桌面 + 移动端浏览器

### 6.2 Out of Scope for MVP

- 赛季/年度积分重置机制 → 数据结构预留，v2 实现
- 个人战绩统计（投票胜率、连胜记录）→ v2
- 投票截止提醒/消息推送 → v2
- 微信登录 → 视需求评估
- 外部赛马数据 API 对接 → 长期愿景
- 管理员日志/审计系统 → v2
- 多语言 → 长期愿景

## 7. Success Metrics

**Primary**
- **SM-1**: 投票效率 — 用户平均在 30 秒内完成一次投票操作。验证 FR-16、FR-26。
- **SM-2**: 积分准确率 — 任意一场比赛结算后，系统积分与人工按规则计算结果 100% 一致（零差异）。验证 FR-12 至 FR-15、FR-21。
- **SM-3**: 迁移率 — 前 10 场赛事后，≥90% 的原有问卷竞猜参与者完成至少一次 Guess 投票。

**Secondary**
- **SM-4**: 比赛创建效率 — 管理员在 2 分钟内完成一场比赛创建（含马匹选择）。验证 FR-5、FR-6、FR-10。
- **SM-5**: 性能 — 100 用户、50+ 场比赛数据量下，页面响应时间 ≤ 2 秒。

**Counter-metrics (do not optimize)**
- **SM-C1**: 投票参与率 — 不强制优化。用户有权不参与某场比赛，不应因「参与率低」修改产品逻辑或推送催促。
